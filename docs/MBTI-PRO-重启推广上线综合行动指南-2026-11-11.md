## 0. 一页结论

### 0.1 先给结论

**这次重启不是“再发一批小红书笔记”，而是先修一条能收钱的链路。**

当前最优先的顺序是：

1. **先恢复一个可访问、可测试、可分享的正式站**，否则任何推广都是在给 525 错误页导流。
2. **先修掉三个转化闸门**：强制反馈、强制邮箱、过长测试与不清楚的付费入口。
3. **先卖现有 100 题版本的深度报告，不建议把 100 题直接定成 0.99 元。** 0.99 元只适合后续的 20 题轻测产品。
4. **小红书先做“中间型人格”的内容资产，不要照搬历史人物设定。** 对标账号的真正壁垒是“身份镜像 + 站内闭环 + 自动交付”，不是历史人物本身。
5. **先跑 8 人真人测试和 3 笔真实订单，再放量。** 现在没有支付闭环、没有完整 E2E、没有隐私/退款页面，不能直接大规模投放。

### 0.2 推荐的首发商业模型

| 层级 | 产品 | 价格 | 目的 | 上线时机 |
|---|---|---:|---|---|
| 免费入口 | 100 题测试 + 基础结果（类型、四维、简短画像） | 0 元 | 获客、分享、建立信任 | 第 3 天前 |
| 首发主商品 | 100 题完整深度报告（网页完整内容 + 可选 PDF） | **4.9 元首发，标准价 9.9 元** | 第一笔现金流 | 第 3-5 天 |
| 后续引流品 | 20 题「中间型雷达」轻测 | 0.99 元 | 降低首次决策成本、筛选高意向用户 | 第 30 天后 |
| 后续高客单 | 职业/关系深度报告 | 19.9-29.9 元 | 提升客单价 | 第 60 天后，有数据再上 |

**为什么不是直接把 100 题卖 0.99 元：** 100 题需要 20-30 分钟，0.99 元无法覆盖交付、客服、退款和内容成本；更关键的是，用户付出 20-30 分钟后只付 0.99 元，会形成“低价低质”的心理锚点。对标账号的 0.99 元对应的是更短的测试和更轻的交付，不是同一个商品。

**为什么保留免费测试：** 你的结果页已经有类型、图片、四维光谱和一句总结，这些都是天然分享素材。让用户先看到“像我”的结果，再决定是否为深度内容付 4.9 元，比在测试前收 0.99 元更符合“先证明价值，再收费”的顺序。

## 2. 项目现状审计：技术不是最大问题，上线链路才是

### 2.1 两个公开地址都不能用

#### 正式域名：Cloudflare 525

2026-11-11 实测：

```text
https://mbti-pro.com/
→ Cloudflare Error 525: SSL handshake failed
```

这不是“用户网络不好”，而是 Cloudflare 到源站的 SSL 握手失败。常见原因是源站证书过期、Nginx 没有配置 443、Cloudflare SSL 模式与源站不匹配。域名本身仍在，但当前没有可用的正式产品。

#### GitHub Pages 备用站：HTML 能打开，JS/CSS 全部 404

```text
https://shadowwei5.github.io/MBTI-PRO/
→ HTTP 200，但 HTML 内资源路径是 /assets/index-*.js、/assets/index-*.css
→ 实际资源在 /MBTI-PRO/assets/...
→ 4 个页面实测可见文本均为 0，控制台 3 条资源 404
```

我用真实 Chrome 对 4 个页面做了冒烟测试，结果全部失败：

| 页面 | 结果 |
|---|---|
| 首页 `/` | 可见文本 0 字，3 个 404 |
| `/test` | 可见文本 0 字，404 |
| `/result/ENTJ` | 可见文本 0 字，404 |
| `/result/ENTJ?...` | 可见文本 0 字，404 |

### 2.3 现有转化链路：三个闸门在漏人

#### 闸门一：答完 100 题后强制填写两项人格偏好，才能看结果

`client/src/views/TestView.vue` 在提交后设置 `showFeedbackAfterTest = true`，而 `FeedbackCollector.vue` 要求用户选择“最相处愉快的 16 型”和“最痛苦的 16 型”，否则按钮不可用。

这会造成三个问题：

1. **用户已经投入 20-30 分钟，却在结果前被拦住。**
2. 问题涉及对其他人格的负面评价，容易让用户不舒服。
3. 反馈对用户没有即时价值，却被设计成强制步骤。

建议：把反馈移到结果页底部，改成可跳过的 1-2 个问题；或者用“你愿意用一句话描述自己吗”这种低压力形式。**结果必须先给，反馈后置。**

#### 闸门二：深度报告必须填邮箱 + 生成分享海报才能解锁

`client/src/components/PaywallSection.vue` 当前的非演示逻辑是：

- 必须输入有效邮箱；
- 必须点击“生成分享海报，免费解锁”；
- 解锁后再发送 PDF 到邮箱。

这相当于在用户最想看结果的时候，要求他交出邮箱并完成一次分享动作。对小红书来的用户，邮箱不是常用身份，分享也不一定是当下意愿。结果就是：**用户看到了类型，但看不到最深的内容，然后离开。**

建议：

- 深度报告默认用“购买/兑换码”解锁，**不强制邮箱**；
- 邮箱只用于“可选接收 PDF”；
- 分享海报放在结果页作为传播入口，不与解锁绑定；
- 如果保留免费分享解锁，必须把它明确标成“免费路径”，并让用户可以选择付费路径。

#### 闸门三：100 题 + 20-30 分钟，但没有在入口讲清楚“可以暂停”

首页写“100 道精选题目 / 20-30 分钟 / 无需注册”，这是诚实的，但对小红书碎片场景仍然偏重。好消息是测试页已经把进度存到 `localStorage`，可以断点续答；坏消息是入口没有明确告诉用户“可以中断，下次继续”，用户会在开始前就被时长吓退。

建议把入口文案改成：

> 100 道题，约 20-30 分钟；可以随时退出，下次从上次的位置继续。  
> 先看免费结果，再决定要不要深度报告。

同时把“100 题”拆成 4 个维度的小段落，给用户“已经完成 25%”的成就感，而不是一条 100 题的长进度条。

### 2.4 付费与交付：代码里有价格，但功能是关闭的

`server/src/routes/payment.ts`：

- `ENABLE_PAID_UNLOCK` 默认 false，支付创建接口会直接返回“冷启动阶段已开放免费分享解锁”；
- 代码里价格写死为 `4.90`；
- 支付走 XorPay，返回二维码；
- 回调成功后发报告邮件。

问题在于：

1. **二维码支付不适合小红书内置浏览器。** 用户无法用同一块屏幕扫自己的二维码；必须确认是否有 H5 跳转/收银台方案。
2. **没有兑换码入口。** 如果在小红书店铺卖“深度报告”，用户拿到的是兑换码，而当前站点没有输入兑换码的地方。
3. **没有订单和站内商品的对接。** 支付成功、订单号、退款、重复解锁都没有形成闭环。
4. **打赏组件仍在结果页出现。** 在付费产品还没跑通时，打赏会让用户困惑：“到底该买报告还是打赏？”

**建议首发采用“小红书店铺售卖兑换码 + 站点兑换”的模式，不把二维码支付作为唯一路径。** 站点只负责测试、结果和兑换，交易留在小红书站内。这样既符合平台“站内成交”的方向，也避免内置浏览器无法扫码的问题。

### 2.5 安全与合规：上线前必须处理的 P0

这部分比视觉优化重要。当前代码里存在几个不应该带公开流量的点：

| 问题 | 证据 | 风险 |
|---|---|---|
| 管理统计接口无鉴权 | `server/src/routes/admin.ts` 的 `/api/admin/stats`、`/api/admin/traffic` 没有校验 key | 任何人可读取测试量、类型分布、来源等运营数据 |
| 管理 key 有硬编码兜底 | `admin.ts`、`socialUnlocks.ts` 使用 `mbti-pro-admin-2026` 作为 fallback | 前端 bundle 可被查看，等于公开后台口令 |
| 客户端暴露管理 key | `client/src/services/api.ts` 直接拼 `key=mbti-pro-admin-2026` | 任何人可调用审核、导出邮箱等接口 |
| 公开页面有“管理后台”入口 | `HomeView.vue` footer 链接 `/admin` | 增加被扫后台的概率 |
| 邮箱、反馈、截图上传无频率限制 | `/api/email`、`/api/feedback`、`/api/social-unlocks` | 可被批量灌数据、消耗存储、触发邮件 |
| 没有隐私政策/用户协议/退款说明 | 前端未找到对应页面 | 收集邮箱、人格结果、设备信息，商业收费前必须补齐 |

上线前至少要做：

1. 删除所有硬编码管理员 key，换成服务端环境变量 + 强随机值；
2. 管理接口统一鉴权，最好移到独立后台域名/VPN，不暴露在公开 API 路径；
3. 加 rate limit、请求体大小限制、验证码/签名；
4. 公开页面移除 `/admin` 链接；
5. 补隐私政策、用户协议、退款/售后说明、联系方式；
6. 明确“人格结果仅供自我探索，不构成临床诊断、招聘或保险决策依据”；
7. 如果继续使用“MBTI”作为产品名，补充独立声明，说明与 MBTI 官方机构无关联；商业规模化前建议做商标检索。

### 2.6 其他影响转化的细节

- 首页写“比传统 MBTI 精准 5 倍”，目前没有信效度数据支撑。建议改成“81 种细分组合，更细致地描述中间状态”，避免绝对化宣传。
- 首页引入 Google Fonts。中国大陆网络环境下可能加载慢或失败，影响首屏。建议自托管字体或使用系统字体回退。
- 结果页分享海报依赖 `location.origin/test`，在自定义域名/子路径部署时要重新验证二维码指向。
- `e2e/critical-flows.spec.ts` 的完整 100 题流程被 `test.skip`，目前没有真正的“测试→结果→解锁”全链路自动化。上线前必须补一条。
- 当前没有“开始测试/完成测试/看到付费墙/点击解锁/兑换成功”的事件埋点。现有 UTM 只在完成记录时写入，无法算出从进入到完成的漏斗。

### 2.7 当前上线判定

| 维度 | 判定 | 说明 |
|---|---|---|
| 正式域名 | 红灯 | 525，完全不可用 |
| 静态备用站 | 红灯 | HTML 200，但资源 404，页面空白 |
| 本地产品 | 黄灯偏绿 | 核心流程可跑，移动端无溢出 |
| 支付/交付 | 红灯 | 支付关闭、二维码不适配内置浏览器、无兑换码 |
| 转化体验 | 红灯 | 强制反馈、强制邮箱、长测试入口不清 |
| 安全/合规 | 红灯 | 管理接口、硬编码 key、隐私页面缺失 |
| 内容资产 | 黄灯 | 有 81 张图、海报、视频管线，但未形成小红书内容矩阵 |

**结论：现在不能直接投放。先做“恢复 + 修闸门 + 兑换码 + 内测”，再做内容。**

## 3. 重启策略：把“81 型”翻译成一个具体承诺

### 3.1 定位

不要再用“全球首个 81 型 MBTI”作为主文案。用户不关心你是不是第一个，用户关心的是：

> “为什么我每次测 MBTI 都不一样？”  
> “我明明不是社恐，但社交完真的很累。”  
> “我既不理性也不感性，我是不是有问题？”

81 型的价值是回答这些“中间态”问题。建议主定位：

> **MBTI-PRO：把“卡在中间”的人格说清楚。**  
> 16 型之外，还有 65 种中间组合；你不必被迫选一边。

这句话同时具备：

- 与对标账号的差异（不做历史人物，做中间态）；
- 与 16Personalities 的差异（不是又一个 16 型测试）；
- 与娱乐测试的差异（100 题、四维、可解释）；
- 可持续的内容母题（中间型、关系、职场、自我理解）。

### 3.2 产品阶梯

**首发只做两个层级，不要一次上四个 SKU。**

| 层级 | 内容 | 价格 | 交付 |
|---|---|---:|---|
| 免费 | 100 题测试 + 基础结果（类型、四维、简短画像、分享海报） | 0 | 网页即时 |
| 付费 | 100 题深度报告（人格概览、四维解析、优势、成长、代表人物、可选 PDF） | 4.9 元首发 / 9.9 元标准 | 兑换码解锁网页；PDF 可选邮箱 |

等首发放量后，再考虑：

- **0.99 元轻测**：20 题左右，只输出四维倾向和“中间型雷达”，不承诺完整 81 型结论；
- **19.9 元职业/关系报告**：在完整报告基础上增加场景章节；
- **B 端/校园合作**：团体报告、讲座、社团活动，不和首发抢注意力。

### 3.3 推荐成交路径

```text
小红书笔记/主页
  → 小红书店铺商品「81型人格深度报告兑换码」
  → 订单页自动发货（官方自动发货/订单信息）
  → 用户打开 mbti-pro.com，完成免费测试
  → 结果页看到类型与基础内容
  → 输入兑换码，解锁深度报告
  → 可选填写邮箱接收 PDF
  → 分享海报/结果卡回到小红书
```

为什么不建议“先买 0.99 再测”：

- 你的产品不是短测，用户买了却要花 20-30 分钟，退款和投诉风险更高；
- 先让用户看到结果，再卖深度内容，价值证明更充分；
- 免费测试本身就是分享素材，能带来自然流量。

如果你坚持要对标账号的“先买后测”，则必须做一个独立的 20 题轻测，不要拿 100 题版本硬套。

### 3.4 价格策略

| 方案 | 价格 | 适用 | 风险 |
|---|---:|---|---|
| 0.99 元轻测 | 0.99 | 20 题、3-5 分钟、四维快照 | 利润极低，必须靠后端 |
| **4.9 元首发完整报告** | 4.9 | 当前 100 题版本 | 需要解释“为什么不是 0.99” |
| 9.9 元标准价 | 9.9 | 首发 100 单后 | 需要更强的样例和信任 |
| 19.9 元职业/关系版 | 19.9 | 有复购/口碑后 | 内容交付成本高 |

建议首发做“前 100 单 4.9 元，之后恢复 9.9 元”，但不要用虚假倒计时。价格可以在商品详情里写清楚“首发批次”，并保留调整权利。

### 3.5 7 天 / 30 天 / 90 天

| 阶段 | 目标 | 关键动作 | 不做什么 |
|---|---|---|---|
| D0-D2 | 站点恢复 | 续费/重开服务器、修 SSL、部署、回滚预案 | 不发推广笔记 |

## 5. 网页上线：先恢复，再优化

### 5.1 域名与服务器恢复

当前 `mbti-pro.com` 是 Cloudflare 525。建议按以下顺序处理：

1. **先查腾讯云实例是否还存在。** 如果只是到期/停机，续费恢复通常比新购快；如果实例已释放，再考虑新购。
2. 服务器优先选**腾讯云轻量香港 2C2G**（无需 ICP，面向大陆访问延迟可接受）；如果已有国内备案域名/服务器，则优先国内节点。
3. Nginx 反向代理 `127.0.0.1:3001`，前端静态文件指向 `client/dist`。
4. Cloudflare SSL 设为 **Full (strict)**，源站安装 Cloudflare Origin Certificate 或 Let's Encrypt；不要用 Flexible，容易重定向循环。
5. 部署后先验证 `https://mbti-pro.com/api/health`，再验证首页。
6. 保留一台可回滚的旧版本/快照；SQLite 数据库每天备份。

如果 48 小时内无法恢复正式站：

- 先把域名指向一个**可用的静态维护页**，写清“正在升级，预计恢复时间”和站内联系方式；
- 不要把 525 页面直接暴露给小红书用户；
- 维护页不要收集敏感信息，不要放虚假倒计时。

实现方式可以是同服务器的 `/api/events`，只存匿名 session、事件名、时间、页面、UTM，不存答案和人格结果；也可以接国内合规的分析工具。不要为了埋点收集身份证、手机号等无关信息。

核心日报：

- 访客数、测试开始数、完成数、完成率；
- 第 10/25/50/75/100 题流失；
- 结果页付费墙曝光 → 兑换点击 → 成功；
- 退款、客服工单、异常订单；
- 小红书来源的 UTM/兑换码批次。

### 5.5 SEO 与长期流量

SEO 不是首发优先级，但不要丢掉：

- 81 个类型页要有独立 title/description/正文，当前服务端只对 `/result/:typeCode` 做了动态 meta；
- SPA 对百度的抓取不稳定，后续用预渲染/静态生成输出 81 个页面；
- 每页围绕“中间型/类型名/关系/职场”做长尾，不要堆关键词；
- 提交百度/Google 站长平台，保留 sitemap；
- GitHub Pages 演示站继续 `Disallow`，避免和正式站竞争。
