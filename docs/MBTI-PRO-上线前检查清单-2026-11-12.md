## 3. P0：上线前必须解决（按此顺序）

### 3.1 修 Cloudflare 525（最高优先级，只能在服务器/Cloudflare 侧做）

525 = Cloudflare 与源站之间 SSL 握手失败，**本地改代码解决不了**。按顺序排查：

```bash
# 在服务器上执行
ss -lntp | grep -E ':443|:3001'          # 源站 443 是否在监听
systemctl status nginx                    # nginx 是否存活
nginx -t                                  # 配置是否正确
curl -sS http://127.0.0.1:3001/api/health # 后端是否健康
pm2 list                                  # 或检查 nohup 进程
```

Cloudflare 面板检查：
1. **SSL/TLS → 概述 → 加密模式**：建议 `Full (strict)`；若源站没有有效证书却被设为 Full/Strict，必然 525。
2. 源站证书是否过期、是否覆盖 `mbti-pro.com`（`openssl x509 -in <cert> -noout -dates -text | grep DNS`）。
3. **临时把该记录改为「仅 DNS / 灰色云」直连测试**：若直连 443 正常，则问题在 CF 加密模式或 CF 回源证书；若直连也失败，则问题在源站 nginx/证书。测完记得切回。
4. 若服务器已停机，先恢复实例与 nginx，再谈部署。

### 3.2 提交代码并启用部署工作流

### 3.3 生产 `ADMIN_KEY`

```bash
openssl rand -hex 32        # 生成强随机值
```

写入 GitHub Secrets `ADMIN_KEY`，并确认服务器 `server/.env` 中存在同名变量。当前本地 `.env` 没有该变量（缺失时后台 403，属 fail-closed 设计，但上线后看不到统计）。

### 3.4 替换联系方式占位符

把 `client/src/views/LegalView.vue` 里的 `CONTACT_EMAIL_PLACEHOLDER` 换成真实邮箱（或删掉该行、只保留小红书店内渠道）。**带占位符上线等于给不出联系渠道**，会影响店铺资质与消费者信任。

### 3.5 补「敏感个人信息单独同意」的显式勾选

隐私政策目前写的是「点击开始测试即表示同意」。人格结果属敏感个人信息，《个人信息保护法》要求**单独同意**。建议在兑换后进入测试前加一个明确的勾选项（不默认勾选）。这一步涉及首页/答题页交互，属于另一个对话的 UI 范围，**需要你确认后我再改**，避免并行冲突。

### 3.6 跑 3 笔真实订单

按 `docs/access-code-fulfillment.md` 2.3 的自动发货模板，完整走：下单 → 自动发货 → 兑换 → 40 题 → 完整报告 → 1 笔退款 → 1 笔补发。**这是 G2 从「资格确认」变成「链路跑通」的唯一判定标准。**
