### 第 1 条是本次下滑的最大嫌疑

「ENTJ / ENTP」是**产品内部编码**，而「J人 / P人」是**平台上的口语词**。

证据：平台自己给出的「猜你想搜」是 **「漫威mbti」** —— 这是小红书内部的联想词，说明平台把这类内容挂在 **mbti** 这个流量词下面，而不是挂在 ENTJ/ENTP 下面。

用 ENTJ/ENTP 做标题，等于：
- 搜「漫威 mbti」的���根本不会命中；
- 读者看到两个字母缩写，**不知道是什么**，直接划走；
- 「J人」「P人」在站内是高频词、人人会搜，标题里却一个都没有。

## 三、真正的三个病根（不是「数据差」这么简单）

### 病根 1：标题在讲「术语」，而不是在讲「读者自己的事」

对比：
- 我写的：「钢铁侠是J人还是P人」→ 读者能立刻判断「这是说我」
- 你发的：「钢铁侠到底是ENTJ还是ENTP？」→ **读者得先知道 ENTJ 是什么**

小红书搜索行为里，用户搜的是「J人」「P人」「mbti」，不是「ENTJ」。

### 病根 2：正文第 6 行还在讲「第 7 张图」，把读者当成了会看图的人

实测正文原句：
> 「第 7 张图是原题：「我喜欢把事情安排得井井有条…」」

小红书图文的阅读顺序是**先看图还是先读文，因人而异**，但绝大多数用户是**刷到封面 → 看正文前两行 → 决定要不要点开**。

正文里出现「第 7 张图是原题」这种**图序指引**，等于要求用户必须点开图才能理解文案——这是把单向阅读变成闯关。

**正确的写法是：把题目原文直接写进正文**，不要指路。

### 病根 3：9 张图的第 7 张（题目页）承载了最多信息，但没有钩子

P7 是「原题 + 五档量表 + 四维坐标条」，信息密度极高，但**没有一句让人想读下去的话**。刷到第 7 张的人，已经看了 6 张纯文字叙述的卡，划走概率极高。

## 四、我犯的两个错（也要记下来）

1. **把「我改过的标题」当成你已经发了。** 我昨晚交付的是「钢铁侠是J人还是P人」，但你实际发的是 ENTJ/ENTP 版本。我当时没有在发布后核对前台，只能看到素材包。这个错误应该在交付时就说清「标题必须用这个，一字不改」。

2. **Day2 只改了文案和 P7/P8，没改「图文结构本身」。** 现在看，9 张图的节奏是「封面 → 争议 → J → P → 另三维 → 结论 → 题目 → 人物 → 互动」，**前 6 张全是文字**，中间没有任何视觉锚点。

## 五、Day3 的设计原则（基于以上诊断）

1. **标题只允许出现平台口语词**：J人 / P人 / mbti / 性格，禁止 ENTJ / ENTP 这类编码。
2. **正文不出现「第 X 张图」**，题目原文直接写进正文。
3. **正文前两行必须自带钩子**，不能靠封面兜底。
4. **9 图里至少 3 张要有强视觉**（人物 / 画像 / 界面感），不能全是文字叙述。
5. **标题与首行正文必须出现同一个搜索词**，把「漫威 mbti」这类联想词占住。
