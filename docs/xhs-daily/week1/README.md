### 6.2 两种口径要分开

| 口径 | 用在哪 | 正确写法 | 不能写 |
|---|---|---|---|
| **档案配人物**（本 7 天） | 已确定某个类型坐标，用项目已有的人物侧写帮助理解 | 「档案里给 ABCD 配的主人物是曾国藩」「这个坐标的参照是哥德尔」 | 「曾国藩就是 ABCD」「他测过我们的测试」 |
| **坐标演示**（马斯克 / elon 篇） | 用有争议的名人反推坐标 | 「如果把他放进 81 型坐标系，争论的是同一条轴的两端」 | 「马斯克就是 INTD」（项目里马斯克仍归 INTJ） |

马斯克篇的思路和这次的人物钩子是**互补的两类**：前者是「名人 → 坐标」，后者是「坐标 → 档案人物」。两篇都保留，但每周名人争议题材最多 1 篇。

### 6.3 四条红线

1. 不写「本人测评 / 本人推荐 / 同款 / 授权」——11-06 公告明确禁止未经授权借用明星、专业人士、机构名义虚构推荐关系。图上固定标注「档案人物 · 非本人测评」。
2. 不放真人照片、AI 仿肖像、签名或品牌 logo；人物卡只用文字。
3. 不编造私生活、不使用网络伪名言；只取 `FEATURED_PROFILES` 里的公开经历（图上是忠实精简，正文是同一段经历的展开）。
4. 不用「某人就是某型」的判定句，一律用「档案里配的是 / 参照是 / 把他的故事收进档案」。

### 6.4 避免 7 天同句式

人物段每篇换一种切入角度，防止连续 7 天套同一模板（这本身就会撞「模板化批量铺量」）：

| 天 | 切入方式 |
|---|---|
| D+1 | 「档案里给…配的主人物是…」+ 不是本人测过 |
| D+2 | 设问「为什么放的是范蠡？」+ 切换与收手 |
| D+3 | 「最耐人寻味的参照是…」+ 用不完备定理类比边界 |
| D+4 | 「换成一个人可能更好懂」+ 工程系统类比不偏不倚 |
| D+5 | 「很多人以为…可他同时…」+ 两套框架并存 |
| D+6 | 「不只是中间档有档案」+ 端值坐标也有人物 |
| D+7 | 「最容易被误读的大概是…」+ 沉默不等于没立场 |

### 6.5 发现的一处产品数据瑕疵（未改数据，如实记录）

`server/src/content/types.ts` 的 `CELEBRITY_MAP` 里，**曾国藩同时出现在 `ABCD` 与 `EBCD`**，与该文件「保证 81 型代表人物各不相同，无重复使用」的注释矛盾。本素材包用的是 `FEATURED_PROFILES` 的**主人物**（ABCD=曾国藩、EBCD=范蠡），因此图文里不重复；但结果页若展示完整 `CELEBRITY_MAP`，两天都会出现曾国藩。这属于产品侧数据问题，**本轮未改动任何生产数据**，如需修复请单独确认。
